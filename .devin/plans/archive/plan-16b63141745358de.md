# Per-style files: constants split, strategies split, style-card script

Reorganize fighting-style tuning surfaces into per-style files — move XX_* constants from balance.ts into combat/styles/<code>.ts, split strategies.ts into stylePassives/strategies/<style>.ts — and add a scripts/style-card.ts view that prints one style's whole tuning surface; all moves verbatim, barrels preserve the public import surface.

## Summary

Give each fighting style its own constants file and its own strategy file, and add a `scripts/style-card.ts` that prints a style's complete tuning surface in one screen. All moves are **verbatim/mechanical** — no value changes, no inline-magnitude lifting. The shared balance layers (`STYLE_PENALTIES`, `STYLE_SKILL_FLOORS`, `MATCHUP_MATRIX`) stay centralized by design — the plan deliberately does **not** split them.

### 4. `scripts/style-card.ts` — the per-style tuning view

`bun run scripts/style-card.ts <AB|BA|…>` prints one screen:

- `STYLE_PENALTIES` row + `STYLE_SKILL_FLOORS` row, labeled `[ATT PAR DEF INI RIP DEC]`
- `MATCHUP_MATRIX` row (style vs each) and column (each vs style), via `getMatchupBonus`
- `tempo` + `enduranceMult` (via `getTempoBonus`/`getEnduranceMult`)
- `STYLE_IDENTITY` entry (`identity.ts`)
- The style's exported constants — `import * as` each styles module via a `code → module` map (e.g. `ws: await import('@/constants/combat/combat/styles/ws')`), printed as name = value
- Sample `getStylePassive` / `getKillMechanic` outputs at opening/mid/late contexts (the passive "shape" at a glance)

`bun run scripts/style-card.ts --all` (or no arg) prints the cross-style **tempo/enduranceMult table** — the comparison view lost by splitting `strategies.ts`. Reuse `STYLE_KEY`/`STYLE_CODE` from `./lab-overrides`.

## Risks / Considerations

- **`STYLE_PENALTIES`, `STYLE_SKILL_FLOORS`, `MATCHUP_MATRIX` are intentionally not split** — they're cross-style comparison instruments; the antisymmetry guardrail and the two-layer (power vs. matchup) discipline depend on them staying central. The style-card script is what restores the "everything about style X" view without fragmenting them.
- **Dup-guard registration**: if the scanner flags strategy-file preamble echoes, they're registered in `EXEMPT_PAIRS` knowingly — same category as the existing shard-boundary exemptions. Not a failure mode, part of the process.
- **Determinism**: no RNG consumption paths change; constant values are literal moves. Seeded output is bit-identical.
- **No behavior change**: this is a pure reorganization. If any test fails beyond import-path breakage, the move wasn't verbatim — fix the move, not the test.
- Follow-up (not in this plan): lifting the ~60 inline magnitudes inside `getPassive`/`getKillMechanic` into the per-style constants files — the fuller "one file per class" state, deliberately deferred to keep this diff reviewable.
