### 1. `verify-implementation`
Adapted from the donor skill's structure. SL failure classes:
- **Tautological tests** (unchanged).
- **Vertical-slice gaps** — SL chain: component → `useGameStore((s) => s.<action>)` in `src/state/slices/` → engine service → store `set()`; heavy path: UI → `engineProxy.<job>` (`src/engine/runtime/workerProxy.ts`) → FIFO `jobQueue` in `src/engine/runtime/worker.ts` → `commitWorkerResult` → `store.loadGame`. An engine fn no slice/job reaches, or a slice action no UI calls = dead.
- **Determinism violations** — `Math.random`/`Date.now`/`crypto.*` in `src/engine` (grep); draws come from `ctx.rootRng`/passed rng (`resolveRng` fallback precedent); narrators draw from the isolated narration rng; `playerFacing` passes must not carry mechanics (skipped headless). Known open offenders are registered in `docs/MEGAPLAN_BACKLOG.md` (V26-D3 `meta.createdAt`, V26-D4 gazette crypto fallback) — distinguish from new violations.
- **Two-surface divergence** — fixture-vs-world (combat-balance's known gap), narrated-vs-headless, autosim-vs-interactive.
- **Hidden regressions** — always full `bun run test`; `bun run test:slow` when sim/pipeline/economy/balance paths are touched (per `.claude/CLAUDE.md` discipline).
- **Harness false positives** — call functions exactly how production calls them; SL's fixture/snapshot proxy exaggerates gaps (rank candidates there, confirm in world on seeds 12345/777/2024).
Procedure (kept): diff → trace vertical slice → independent seeded empirical check → full suite + `bun run type-check` + determinism greps → bisect on regression → re-confirm on clean HEAD → report with verdict table (`file:line` evidence per claim).
SL quick-reference footer: `bun run test` / `bun run type-check` (runs `bunx tsr generate` then typescript7 `tsc --build --force` — regens `routeTree.gen.ts`), `bun run test:slow`, `bun run e2e`; fixtures at `src/test/_fixtures/factories.ts`; store reset sentinels `src/test/_setup/stateReset.test.ts`.

### 4. `add-player-action`
Rewritten for SL's two-lane path:
- **Cheap synchronous lane** — UI-facing marks/settings → slice action `set()` in the right slice (`src/state/slices/`: `economySlice` `addFunds`/`deductFunds` precedent with `canTransact` guard; `worldSlice/{playerActions,boutActions,combatActions,promoterActions}`; `rosterSlice`, `tournamentSlice`, `progressionSlice`, `bookmarksSlice`, `avatarSlice`). UI calls `useGameStore((s) => s.<action>)`.
- **Engine lane** — domain logic stays pure in `src/engine/<domain>/` (service takes state, returns changes; seeded rng only).
- **Heavy sim lane** — add a method to the `engine` object in `src/engine/runtime/worker.ts` behind `enqueueSim` (narrative preload + cancellation semantics); call via `engineProxy.<job>` (`workerProxy.ts` lazy-spawns the Comlink worker); results commit through `commitWorkerResult` → `store.loadGame` in `src/state/createStore.ts` (serialization boundary: `stripNonSerializable`/`reconstructGameState`; worker owns structuredClone'd states — `mutableInput` convention).
- What NOT to do: no sim work inside slice `set()`; never bypass `jobQueue` (overlapping calls interleave at awaits); never skip the `loadGame` commit; no `Math.random`/`Date.now` in `src/engine`.
- Verify a real UI control reaches it (cross-ref verify-implementation).
